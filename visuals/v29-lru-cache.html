LRU Cache Internals

A hash map finds a node in O(1). A doubly linked list keeps the nodes in use order, so moving or removing a node is also O(1). Most recent sits next to head; the least recent waits next to tail to be evicted.

    Say this in the interview

    "I use a Map<key, Node> plus a doubly linked list with dummy head and tail. get looks up the node, unlinks it and adds it after head. put updates or inserts after head, and if size is over capacity it removes tail.prev from both the list and the map. Every operation is O(1)."

    The code

    class Node<K, V> {
  prev!: Node<K, V>; next!: Node<K, V>;
  constructor(public key: K, public value: V) {}
}

class LRUCache<K, V> {
  private map = new Map<K, Node<K, V>>();
  private head = new Node<K, V>(null as K, null as V); // dummy
  private tail = new Node<K, V>(null as K, null as V); // dummy
  constructor(private capacity: number) {
    this.head.next = this.tail; this.tail.prev = this.head;
  }
  get(key: K): V | undefined {
    const n = this.map.get(key);
    if (!n) return undefined;
    this.unlink(n); this.addFront(n);
    return n.value;
  }
  put(key: K, value: V) {
    const old = this.map.get(key);
    if (old) { old.value = value; this.unlink(old); this.addFront(old); return; }
    if (this.map.size === this.capacity) {
      const lru = this.tail.prev;
      this.unlink(lru); this.map.delete(lru.key);   // keep key in node for this
    }
    const n = new Node(key, value);
    this.map.set(key, n); this.addFront(n);
  }
  private unlink(n: Node<K, V>) { n.prev.next = n.next; n.next.prev = n.prev; }
  private addFront(n: Node<K, V>) {
    n.next = this.head.next; n.prev = this.head;
    this.head.next.prev = n; this.head.next = n;
  }
}

    Why these two structures

    OperationArray / list onlyMap onlyMap + doubly linked list
    Find a keyO(n) scanO(1)O(1) via the map
    Move to most recentO(n) shiftNo order to move inO(1): 4 pointer writes
    Find least recentO(1) at the endO(n) scan of timestampsO(1): tail.prev
    Remove a middle nodeO(n)O(1)O(1), needs the prev pointer (singly linked is not enough)

    Check yourself

    Why store the key inside the node?
    On eviction you only have tail.prev. You need its key to delete the map entry too.
    What do the dummy head and tail buy you?
    No null checks: every real node always has a prev and a next. Insert and unlink are the same four lines for the first, middle and last node.
    Can a JS Map alone do LRU?
    Yes, for a quick version: a Map iterates in insertion order. On get, delete then set to move a key to the end; evict map.keys().next().value. Interviewers usually want the explicit list too.
    How is LFU different?
    Evict the least frequently used key. Keep a map from frequency to a linked list of nodes and track the minimum frequency, still O(1).
