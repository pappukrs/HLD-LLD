Command: Undo and Redo

Every edit is an object with execute() and undo(). The editor keeps two stacks. Undo pops a command and reverses it; redo replays it. Any new edit clears the redo stack, because that future no longer exists.

Editor log

    Say this in the interview

    "Each edit is a command object that knows how to execute and undo itself, and stores what it needs to undo, like the deleted text. The editor pushes executed commands on an undo stack. Undo moves a command to the redo stack; any new command clears redo. I cap the history size and merge fast typing into one command."

    The code

    interface Command { execute(d: Doc): void; undo(d: Doc): void; }

class InsertText implements Command {
  constructor(private pos: number, private text: string) {}
  execute(d: Doc) { d.insert(this.pos, this.text); }
  undo(d: Doc) { d.remove(this.pos, this.text.length); }
}

class DeleteText implements Command {
  private removed = '';
  constructor(private pos: number, private len: number) {}
  execute(d: Doc) { this.removed = d.remove(this.pos, this.len); }
  undo(d: Doc) { d.insert(this.pos, this.removed); }
}

class Editor {
  private undoStack: Command[] = [];
  private redoStack: Command[] = [];
  run(cmd: Command) {
    cmd.execute(this.doc);
    this.undoStack.push(cmd);
    this.redoStack = [];          // a new edit kills the old future
  }
  undo() {
    const cmd = this.undoStack.pop(); if (!cmd) return;
    cmd.undo(this.doc); this.redoStack.push(cmd);
  }
  redo() {
    const cmd = this.redoStack.pop(); if (!cmd) return;
    cmd.execute(this.doc); this.undoStack.push(cmd);
  }
}

    Command vs Memento for undo

    Command (store the change)Memento (store a snapshot)
    What is savedThe operation plus the data to reverse itThe whole state before the change
    MemorySmall, grows with the size of the editsLarge for big documents (copy per step)
    Undo logicYou write undo() for each commandFree: restore the snapshot
    RiskA buggy undo() corrupts stateMemory blow-up; use a cap or structural sharing
    Good forText editors, drawing tools, KV store transactionsForms, small game state, config editors

    Check yourself

    Why must DeleteText store the removed text?
    Undo has to put it back, and after the delete the text is gone from the document. The command keeps the only copy.
    Why clear redo on a new command?
    Redo commands were built for the old document. After a new edit the positions no longer match, so replaying them would corrupt the text.
    How do you stop every keystroke from being its own undo step?
    Merge: if the new insert continues the last one (next position, within about a second), extend the last command instead of pushing a new one.
    How would you add a "macro" of several edits?
    A CompositeCommand that holds a list: execute runs them in order, undo runs their undo() in reverse order.
