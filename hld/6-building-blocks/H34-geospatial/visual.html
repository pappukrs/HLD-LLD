Geohash and Quadtree

"Find drivers near me" cannot use a normal index on (lat, lng). A geohash turns a 2D point into a string, so nearby points share a prefix. A quadtree splits only the busy areas.

Say this in the interview

"Drivers send their location every few seconds. I'll store each one under its geohash in Redis GEO, sharded by city. For a 2 km radius I use length 5 cells (about 4.9 km). To find nearby drivers I query the rider's cell plus its 8 neighbours, then sort the candidates by real distance. If density varies a lot, I'd use a quadtree that splits busy cells, or Uber's H3 hexagons."

How a geohash is built

  • Split longitude in half: right half = 1, left = 0. Then split latitude the same way. Keep alternating.
  • Every 5 bits become one base32 character (0-9, b-z without a, i, l, o).
  • Each extra character makes the cell 32 times smaller.
  • A shared prefix means "same cell". But two close points can have different prefixes if a cell border is between them.
  • Redis GEOADD / GEOSEARCH store a 52-bit geohash as the sorted-set score.

Check yourself

Why not just index lat and lng separately?
A B-tree on lat finds a thin band across the whole world, and one on lng finds another band. The database must intersect two huge sets. A geohash turns the 2D search into a 1D prefix range, which one index handles well.
Which geohash length do you pick for "drivers within 2 km"?
Pick a cell a bit bigger than the radius: length 5 (≈4.9 km). Length 6 cells are only 0.6 km tall, so 9 of them cover 1.8 km north to south, which is less than a 4 km wide circle. Query the cell and its 8 neighbours, then filter by real distance. If you find too few results, drop one character and search a bigger area.
Two points 10 m apart have geohashes with no common prefix. How?
They sit on a big cell border, for example on each side of the equator or the 0° meridian. That is why you always search the neighbours, never only the prefix.
500k drivers update every 4 s. Where does the index live?
In memory: Redis GEO (a sorted set with a 52-bit geohash score), sharded by city. That is 125k writes per second, and the current position does not need durability, because the next update comes in 4 seconds. Old entries are dropped by a last-seen check. The full stream goes to Kafka for history.
Why does a quadtree help in a city?
A fixed grid puts hundreds of drivers in one downtown cell and zero in the desert. A quadtree splits a cell only when it has more than N points, so every leaf holds a small, similar number of points.
