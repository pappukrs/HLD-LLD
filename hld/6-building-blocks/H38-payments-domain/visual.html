Payments: ledger, PSPs, reconciliation

One ₹1,000 card payment, with everything that goes wrong in real life: a double click, a PSP timeout, duplicate and late webhooks, a partial refund, and a nightly reconciliation that finds what the online path missed.

Request in flight Current state / entry Confirmed / matched Lost / rejected / break

Say this in the interview

"A payment is a forward-only state machine. The create API takes an Idempotency-Key and every PSP call carries our attempt id. A timeout means UNKNOWN, not FAILED: a poller and webhooks resolve it. Each transition writes balanced double-entry rows in paise plus an outbox event in one transaction, keyed by event so it posts once. A nightly job reconciles the ledger with the PSP settlement file and the bank statement."

The key lines

if (!NEXT[p.status].includes(to)) return; // forward-only
if (journal.has(eventKey)) return;         // once per event
assert(sum(entries) === 0n);               // double entry
tx(() => { update status; insert journal;
           insert entries; insert outbox });
on timeout: status = 'UNKNOWN'             // never re-charge

Check yourself

Why is a timeout not a failure?
The PSP may have charged the card and only the response was lost. Retrying with a new reference charges twice. Ask the PSP by your reference instead.
Why do ledger entries always sum to zero?
Every rupee that leaves one account enters another. If a transaction does not balance, money was created or lost, so the insert is rejected.
A "failed" webhook arrives after the payment is CAPTURED. What do you do?
Log it and ignore it. States only move forward; CAPTURED to FAILED is not a valid transition.
Why keep reconciliation if webhooks and polling work?
Webhooks get lost, pollers give up, fees and chargebacks change amounts. The settlement file and bank statement are what actually happened.

Numbers

  • Card settlement: T+1 to T+2, minus MDR + 18% GST on the fee
  • UPI: ~20 billion transactions a month (2025)
  • Stripe retries webhooks for up to 3 days
  • Store paise as BIGINT; never floats
