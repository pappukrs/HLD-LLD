System Design Lab H01 · Basics

How to run a 45-minute HLD round

Watch the whiteboard fill up in the right order: scope, numbers that decide something, APIs, one end-to-end diagram with a write and a read walked through it, a check-in, two problem-specific deep dives, and a wrap-up on failures.

Try it: Problem
On the board Request walk / clock Decision / fix Risk / SPOF

Say this in the interview

"Before I design, I'd like a few minutes on requirements and scale. I'll focus on the core flows and keep the rest out of scope unless you want it."

"I have the end-to-end design. The interesting parts are X and Y. Which would you like me to go deeper on?"

"The main risks left are the single primary and the hot key. With more time I'd add multi-region failover and these four alerts."

Phase checklist

  • 0–5 3–5 functional, non-functional, out of scope
  • 5–10 peak QPS, storage/year, read:write, each with a decision
  • 10–15 3–5 endpoints, entities, lookup keys
  • 15–25 one diagram; walk 1 write and 1 read
  • 25–40 2–3 deep dives unique to the problem
  • 40–45 SPOFs, 10× plan, metrics

Check yourself

Minute 20, no diagram. What now?
Say "let me put up the high-level design now", draw the simplest end-to-end version in 3–4 minutes, then deep dive.
Why walk one write and one read?
It proves the diagram actually works end to end and shows where the cache, queue and DB sit on the hot path.
Which deep dives for payments?
Idempotency, the ledger, reconciliation, provider failover. Not the load balancer.
"What if this box dies?"
Stateless: health checks route around it. Stateful: a replica is promoted; say what data can be lost and the user impact.
