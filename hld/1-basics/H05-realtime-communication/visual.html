Polling, SSE and WebSockets

The server has new data. How fast does the client see it, and how many requests are wasted on the way? We send the same three messages over four transports, then scale WebSockets across many servers and watch heartbeats catch a dead phone.

Say this in the interview

"For one-way updates like notifications or live scores I'd use SSE: it is plain HTTP and reconnects by itself with Last-Event-ID. For two-way, low-latency traffic like chat I'd use WebSockets. Gateways are stateful, so I'd add a pub/sub channel per user (or a user → gateway registry) so any server can reach any user. Clients reconnect with backoff and jitter, then fetch missed messages after their last message id."

What bites in production

  • Load balancers and proxies close idle connections (AWS ALB: 60 s by default). Send heartbeats every 20–30 s.
  • Each open connection costs memory and a file descriptor. Plan servers by concurrent connections, not by QPS.
  • A deploy or crash drops thousands of sockets at once. Without jitter, they all reconnect in the same second.
  • Some proxies buffer responses, which breaks SSE. Turn buffering off (for example X-Accel-Buffering: no on Nginx).

Check yourself

Why not use WebSockets for everything?
They are stateful. You need sticky connections, heartbeats, your own reconnect logic and a way to route messages between servers. HTTP caching and normal auth middleware do not apply. If data only flows server → client, SSE is simpler.
With long polling, a message arrives while the client is reconnecting. Is it lost?
Only if the server forgets it. The server must buffer messages per client, or the client sends a cursor (last seen id) with each new request and the server returns everything after it.
A user has a phone and a laptop on two different gateways. How do both get the message?
Both gateways subscribe to the channel user:B. A publish reaches every subscriber, so each gateway delivers to its own socket.
How many WebSocket servers do you need for 10M concurrent users?
If one tuned server holds about 100K idle connections, you need about 100 servers, plus headroom so the rest can absorb a failed server's users.
