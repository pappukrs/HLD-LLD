Domain modelling: make wrong states impossible

Raw numbers pass through a value-object factory and come out valid or not at all. A payment moves through a discriminated union with a transition table. Every broken rule becomes a named error that maps to one HTTP status.

Say this in the interview

"Money is an immutable value object in paise with a currency, built by a factory that validates. The payment is a discriminated union on status, so a captured payment always has a txnId, and a transition table rejects illegal moves like a late duplicate webhook. Every broken rule is a named DomainError with an HTTP status, mapped by one catch at the boundary."

Check yourself

Why a private constructor on Money?
So the only way in is the factory that validates. If you hold a Money, it is valid.
Entity or value object: a shipping address?
A value object. No identity of its own; you replace it as a whole. The user who owns it is an entity.
What does the never default buy you?
When someone adds a new status and forgets to handle it, the switch stops compiling.
Throw or return a Result?
Throw typed errors for broken rules. Return a Result when failure is a normal outcome, such as parsing input.
