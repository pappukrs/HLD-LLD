Classes, interfaces and types

An interface is a contract that disappears at compile time. A class is a blueprint that makes real objects. Union types describe states. Watch what exists at compile time, what exists at runtime, and what the compiler stops for you.

Say this in the interview

"Boundaries like the payment gateway and the repository are interfaces, and classes implement them. Statuses are union literals and the entity is a discriminated union, so a captured payment always has a transaction id and a never check catches a missed state. Rules like a wallet balance sit behind private fields and methods."

Check yourself

Can you write x instanceof PaymentGateway?
No. The interface is erased, so there is nothing to check against at runtime. Use instanceof on a class, or write a type guard isGateway(x): x is PaymentGateway.
Why does a plain object pass as a PaymentGateway?
TypeScript is structural: if the shape matches, the type matches. implements only asks the compiler to check the class early.
What does the never line in the switch buy you?
If someone adds a new status to the union and forgets a case, the leftover value is not never, so the code stops compiling. Missed states are caught at build time.
Is private real privacy?
Only at compile time. (obj as any).field reads it at runtime. #field is enforced by the JavaScript engine.
