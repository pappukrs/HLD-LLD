Composition over inheritance

A notifier needs channels (email, SMS, push) and optional features (retry, logging). First we build it with subclasses and watch the classes multiply. Then we give one object parts it can hold, combine and swap at runtime.

The code behind the scene

// inheritance: one class per combinationclass EmailWithRetryAndLogging extends EmailWithRetry { ... }// composition: parts plugged ininterface Channel { send(to: string, msg: string): Promise<void>; }interface SendPolicy { wrap(next: SendFn): SendFn; }class Notifier {  constructor(private channel: Channel, private policies: SendPolicy[] = []) {}  setChannel(c: Channel) { this.channel = c; }    // swap at runtime  send(to: string, msg: string) {    const fn = this.policies.reduceRight((next, p) => p.wrap(next),                (t, m) => this.channel.send(t, m));    return fn(to, msg); }}const n = new Notifier(new EmailChannel(), [new Logging(), new Retry(3)]);

Say this in the interview

"Notifications vary on two axes: the channel, and extra behaviour like retry and logging. Inheritance would give channels times feature combinations, so I make each axis an interface. The notifier holds one channel and a list of policies, so retry is written once, and I can switch a user to SMS at runtime. I keep extends for real, shallow IS-A relations."

Inheritance vs composition

InheritanceComposition
RelationIS-A, fixed when the object is createdHAS-A, chosen and changed at runtime
Classes for C channels, F featuresC × 2^FC + F + 1
Reuse a feature across typesNo (one parent only): copy itYes: any class can hold a RetryPolicy
CouplingChild sees parent internals (fragile base class)Only the part's public interface
TestingDrags the whole parent inPass a fake part
Still right forCustom errors, a shallow stable base, Template MethodAnything that varies independently

Check yourself

Why did CountingMap report 0 writes after 2 entries?
The Map constructor called this.set() before the child's field writes = 0 was initialised, so the field reset the count afterwards. The child depended on a parent detail it could not see.
What is an "axis of change"?
A thing that varies independently of the rest, like the channel, or the set of extra features. Each axis becomes its own interface and its own field.
Which patterns are just composition?
Strategy, Decorator, State, Bridge, Composite. Each keeps another object in a field and delegates to it.
Is extends now banned?
No. "Prefer" composition. A true subtype with a shallow, stable parent is fine: class NotFoundError extends Error.
