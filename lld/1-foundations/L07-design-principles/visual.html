Say this in the interview

"Checkout doesn't reach into the wallet. It asks order.canPay(amount), and each object answers for its own data, so when the wallet moves to a ledger only Wallet changes. The GST rule lives in one TaxPolicy, so cart and invoice can't disagree. And I'm not building a plugin system for one payment provider; if more are coming, I'll add an interface then."

Check yourself

Is items.filter(..).map(..) a Demeter violation?
No. It is a fluent chain over data. Demeter is about reaching through objects with behaviour to use their internals.
Why did the loose design survive the wallet change?
Callers only used Wallet.has() and debit(). Swapping a balance field for a ledger changed what is inside, not the methods, so the ripple stopped at the boundary.
Two services both use maxRetries = 3. DRY them?
Only if it is the same decision. Different owners and reasons means incidental duplication; keep them separate.
OCP says add interfaces, YAGNI says don't. Which wins?
Both: interfaces where the problem says behaviour varies, nothing speculative elsewhere.
