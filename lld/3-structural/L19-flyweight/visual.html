Flyweight: share what is the same

Forty seats each carry their own copy of the seat-type data. Only three types exist. A factory hands out one immutable SeatType per type, each seat keeps just row, column and status, and memory drops by over 90%.

Flyweight + factory + context

class SeatType {                       // flyweight: intrinsic, shared
  constructor(readonly name: string, readonly basePrice: number,
              readonly color: string, readonly icon: Uint8Array) {
    Object.freeze(this);
  }
  render(row: string, col: number, status: SeatStatus) { ... }
}

class SeatTypeFactory {
  private cache = new Map<string, SeatType>();
  get(name: string, price: number, color: string) {
    let t = this.cache.get(name);
    if (!t) { t = new SeatType(name, price, color, loadIcon(name));
              this.cache.set(name, t); }
    return t;                            // same object every time
  }
}

class Seat {                           // context: extrinsic only
  priceOverride?: number;
  constructor(readonly row: string, readonly col: number,
              readonly type: SeatType, public status: SeatStatus) {}
}

Try it: is Flyweight worth it here?

Say this in the interview

"A week of seat maps is about 4 million seat objects, but only three seat types. So SeatType is a flyweight: name, base price, colour and icon, immutable, one instance per type from a factory. Each Seat keeps only row, column, status and a reference. That is roughly 8 GB down to under 200 MB. Anything per seat, like a hold or a discount, is extrinsic and never goes into the shared object."

Check yourself

Is "status: BOOKED" intrinsic or extrinsic?
Extrinsic. It differs per seat and per moment. If it lived in SeatType, every seat of that type would look booked.
Why freeze the flyweight?
Thousands of seats share it. One accidental write (price = 0) changes all of them at once.
Flyweight vs object pool?
Flyweights are immutable and used by many at the same time. Pooled objects are mutable, borrowed by one user, then reset and returned.
When is it not worth it?
When objects are few, or the shared part is tiny. 300 seats with a 20-byte type saves almost nothing and adds a factory and a split API.
