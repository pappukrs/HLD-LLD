Memento: sealed snapshots for undo

The editor (originator) packs its private state into a sealed memento. The history (caretaker) stacks those mementos for undo and redo, but can never open them. Only the editor can read one back with restore().

    Say this in the interview

    "The editor is the originator: it creates a snapshot of its own state and is the only class that can read it back. The history is the caretaker: it keeps an undo stack and a redo stack of opaque mementos, clears redo on every new change, and caps the stacks so memory stays bounded. If the state is large, I switch to command-based undo or store diffs."

    Check yourself

    Why does undo() save the current state before restoring?
    So redo has something to return to. Without it, the state you undid is lost.
    Why is the redo stack cleared on a new change?
    Those snapshots describe a future that no longer exists. Redoing them would throw away the new change.
    The caretaker wants to show "Undo: typed Pay" in a menu. How, without opening the memento?
    The originator puts harmless metadata on the memento, like label and at. The caretaker reads only those.
    Can a memento undo a sent payment?
    No. It restores local state only. An external effect needs a compensating action, like a refund.
