Iterator: cursors over hidden storage

The log keeps payments in private segments. Callers get a cursor that answers one question: "what is next?". A generator pauses at yield between calls. Below, an async generator hides cursor pagination and stops fetching when the caller breaks.

Iterator log

    Say this in the interview

    "The topic stores messages in segments, but consumers shouldn't know that. The topic is iterable through a generator, and each consumer group keeps its own offset, like Kafka. For external data I wrap cursor pagination in an async generator: callers write for await, the next page is fetched only when needed, and on break the finally block closes the connection."

    The code

    class PaymentLog implements Iterable<Payment> {
  private segments: Payment[][] = [[]];
  *[Symbol.iterator]() {
    for (const seg of this.segments) yield* seg;
  }
  *from(offset: number) {
    let i = 0;
    for (const p of this) if (i++ >= offset) yield p;
  }
}

async function* allPayments(api: Api) {
  let cursor: string | undefined;
  try {
    do {
      const page = await api.list({ cursor });
      yield* page.items;
      cursor = page.nextCursor;
    } while (cursor);
  } finally { /* close socket / DB cursor */ }
}
for await (const p of allPayments(api)) {
  reconcile(p);
  if (done) break;          // → return() → finally
}

    Check yourself

    Why did cursor A not move when cursor B read?
    Each call to [Symbol.iterator]() or from() creates a new generator with its own paused position. The log is shared; the cursors are not.
    Why was page 2 never fetched?
    The async generator is pull-based. The caller broke after pay_2, so next() was never called again. break called return(), which ran finally.
    Crossing from segment 0 to segment 1: did the caller notice?
    No. yield* moved to the next segment inside the generator. The caller only sees the next value.
    What does next() return after the last item?
    { value: undefined, done: true }, and it keeps returning that. The generator is used up.
