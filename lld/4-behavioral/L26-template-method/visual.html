Template Method: one webhook flow, many providers

The base class owns the steps and their order in handle(). Each provider subclass fills in only verifySignature and parse, and may use the afterApply hook. The shared dedupe step can never be skipped.

    Say this in the interview

    "Every provider's webhook follows the same flow: verify, parse, dedupe by event id, update the payment, reply. I put that flow in an abstract WebhookHandler.handle(), so the order and the dedupe can't be skipped. Each provider implements only verifySignature and parse. Extra per-provider work goes in the afterApply hook. If we need to swap steps at runtime, I inject them as a strategy instead."

    The code (lines light up with the steps)

    abstract class WebhookHandler {  handle(raw: RawWebhook): string {    if (!this.verifySignature(raw)) return this.reply(401);    const e = this.parse(raw.body);    if (seen.has(e.eventId)) return this.reply(200, 'dup');    seen.add(e.eventId); db.set(e.paymentId, e.status);    this.afterApply(e);              // hook    return this.reply(200, 'ok');  }  protected abstract verifySignature(raw: RawWebhook): boolean;  protected abstract parse(body: string): PaymentEvent;  protected afterApply(_e: PaymentEvent): void {}}class StripeHandler extends WebhookHandler { /* 2 steps + hook */ }

    Check yourself

    Which steps can a subclass change, and which can it not?
    It must implement abstract steps, may override default steps and hooks, and must not touch fixed steps or the template method itself.
    Why did the retried Razorpay event not credit twice?
    Dedupe is a fixed step in the base class. Every subclass gets it for free and cannot skip it.
    What is a hook, and why is it empty by default?
    An optional extension point. Empty means "do nothing" so most subclasses can ignore it. Stripe overrides it to alert on failures.
    Where does Node use this pattern?
    Streams: Readable calls your _read(), Transform calls _transform() and _flush(). NestJS lifecycle hooks too.
