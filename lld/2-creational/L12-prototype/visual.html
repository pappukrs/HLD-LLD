Prototype

Make new objects by copying a configured one. The whole pattern is about one question: after the copy, which nested objects are shared and which are owned? Watch the references.

Say this in the interview

"Each notification type starts from a template. I keep templates in a registry and give the class a clone() that copies the nested parts a clone may change, so editing one OTP notification never changes the template. Spread is only a shallow copy. For plain data structuredClone works, but it drops the class prototype, so methods are gone."

Check yourself

const b = { ...a }; b.items.push(x). What happens to a?
a.items also gets x. Spread copies only the top level, so both objects point to the same array.
What does structuredClone(new Money(100, 'INR')) return?
A plain object { amount: 100, currency: 'INR' }. It is not an instance of Money, so money.format() is undefined.
When is a shallow copy enough?
When the nested values are immutable (strings, numbers, frozen objects) or are meant to be shared and nobody mutates them (a reference to a Product). Deep-copy only what the clone will change.
Is JavaScript's prototype chain the same thing as this pattern?
No. Object.create(proto) links to another object to inherit methods; nothing is copied. The Prototype pattern copies state to make a new, independent object.
