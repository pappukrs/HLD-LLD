Simple Factory and Factory Method

Say this in the interview

"Callers only see the PaymentGateway interface. One factory maps the method string to a constructor in a lookup table, and throws on unknown values so the API returns 400 at the boundary. Adding net banking is one new class and one line in the table; checkout, refund and reconcile don't change. If a base class has a fixed algorithm and only the product differs, I'd use the GoF Factory Method: subclasses override createChannel()."

Check yourself

Doesn't the factory still have a switch? Isn't that an OCP violation?
Yes, but it is in one place, and every caller is closed to change. With self-registration (factory.register('UPI', () => new UpiGateway()) in the UPI module) even the factory file stops changing.
Factory vs Strategy?
Factory decides which object to create. Strategy is the object that does the varying work. They usually appear together: the factory creates the right pricing strategy, and the service calls strategy.price().
When should the factory return the same object every time?
When the products are stateless (no per-request fields). Cache one instance per key. If the product holds per-request state, create a new one per call.
Where should the unknown-method check live?
In the factory or in request validation, at the edge. Fail fast with a 400, so the rest of the code can trust it always has a real gateway.
