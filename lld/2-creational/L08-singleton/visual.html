Check yourself

Is if (!instance) instance = new X() thread-safe in Node?
Yes, if the creation is synchronous: the check and the assignment run in one turn of the event loop. If creation is async (await connect()), two callers can both see undefined. Cache the promise: p ??= connect().
Your app runs 4 pods, each with an in-memory singleton rate counter. Limit is 25/min. What is the real limit?
About 100/min, because each pod counts alone. Move the counter to Redis (INCR + EXPIRE) so all pods share one count.
Why do people call Singleton an anti-pattern?
It is global mutable state with a nice name. It hides dependencies, ties code to one concrete class, and leaks state between tests. One instance created in the composition root and injected gives the same "only one" without those problems.
How can a Node app end up with two "singletons"?
Two copies of the same package in node_modules (different versions), worker threads, or the cluster module. Each module copy and each process has its own instance.
